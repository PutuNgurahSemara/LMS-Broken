### Perbaikan 6 Masalah : validasi hanya di frontend, unique pada update yang menolak dirinya sendiri, filter disimpan di session, pagination kehilangan query string, store tanpa redirect, dan satu form tanpa @csrf. (Branch W04)

**1. Validasi hanya ada di Frontend**

a. Letak kesalahannya pada app/Http/Controllers/CourseController.php (Method store()).
 Method store() langsung memasukkan data $request ke database tanpa menggunakan $request->validate(). Atribut validasi HTML (required, min, max) mudah dimanipulasi melalui browser DevTools atau dilewati dengan mengirim request via Postman/cURL. Akibatnya, data tidak valid (seperti SKS 99) bisa masuk ke database.

 b. perbaikannya yaitu Menambahkan $request->validate() pada backend sebelum menjalankan perintah pembuatan data.

 c. Bukti perbaikan

 sebelum: 
 Course::create([
    'code' => $request->code,
    'name' => $request->name,
    'description' => $request->description,
    'sks' => $request->sks,
    'lecturer_id' => $request->lecturer_id,
    'status' => $request->status ?? 'draft',
]);

sesudah:
$validated = $request->validate([
    'code'        => 'required|string|max:20|unique:courses,code',
    'name'        => 'required|string|max:255',
    'description' => 'nullable|string',
    'sks'         => 'required|integer|min:1|max:6',
    'lecturer_id' => 'required|exists:users,id',
    'status'      => 'required|in:draft,active,archived',
]);

Course::create($validated);

**2. Validasi Unique saat update menolak data sendiri**

a. Letak kesalahannya terletak pada pada app/Http/Controllers/CourseController.php (Method store()).
Penggunaan aturan 'unique:courses,code' mengecek seluruh baris di tabel courses. Jika pengguna mengedit mata kuliah (misalnya hanya mengubah deskripsi) tanpa mengubah kode, Laravel mendeteksi kode tersebut sudah ada (milik data itu sendiri) dan menganggapnya sebagai duplikat, sehingga proses simpan gagal.

b. Perbaikannya yaitu menggunakan Rule::unique('courses', 'code')->ignore($course->id) untuk mengecualikan ID data yang sedang diedit dari pengecekan duplikat.

c. Bukti perbaikan 

sebelum: 
'code' => 'required|string|max:20|unique:courses,code',

sesudah :
'code' => [
    'required',
    'string',
    'max:20',
    Rule::unique('courses', 'code')->ignore($course->id),
],

**3. Fitur pencarian dan status disimpan disession**

a. Letak kesalahannya terletak pada app/Http/Controllers/CourseController.php (Method index())
 Menyimpan nilai pencarian ke session(['course_search' => ...]) membuat filter tersebut bertahan secara permanen pada sesi browser pengguna. Ketika pengguna kembali membuka URL /courses tanpa parameter pencarian, filter lama tetap aktif dan menampilkan data yang salah/membingungkan.

 b. Perbaikan yaitu  Mengambil parameter filter langsung dari URL request ($request->input()) tanpa melibatkan session.

 c. bukti perbaikan

 sebelum: 
 if ($request->has('search')) {
    session(['course_search' => $request->search]);
}

if ($request->has('status')) {
    session(['course_status' => $request->status]);
}

$search = session('course_search');
$status = session('course_status', 'active');

sesudah:
$search = $request->input('search');
$status = $request->input('status', 'active');

**4. Pagination menghilangkan Query string filter**

a. letak kesahalan pada app/Http/Controllers/CourseController.php (Method index()).
 Pemanggilan $query->paginate(10) tanpa withQueryString() tidak akan membawa parameter URL pencarian saat berpindah ke halaman berikutnya. Link halaman selanjutnya hanya akan menjadi /courses?page=2 (parameter search dan status hilang), sehingga hasil pencarian kembali tereset.

 b. Perbaikannya yaitu Menambahkan method ->withQueryString() setelah fungsi paginate(10)

 c. Bukti perbaikan

 sebelum: 
 $courses = $query->paginate(10);

 sesudah:
 $courses = $query->paginate(10)->withQueryString();

 **5. Method store() Langsung Menampilkan View (Melanggar Pattern PRG)**

 a. Letak Kesalahan ada pada app/Http/Controllers/CourseController.php (Method store())
Mengembalikan view('courses.index') secara langsung dari request POST membuat browser tetap berada dalam alur POST. Jika pengguna melakukan refresh halaman, browser akan meminta pengiriman ulang form (re-submit form), yang berisiko membuat data tersimpan ganda (duplikat).

b. Perbaikannya yaitu Menerapkan pola Post/Redirect/Get (PRG) dengan mengarahkan (redirect) ke route courses.index setelah data tersimpan.

c. Bukti perbaikan 

sebelum:
Course::create($validated);

$courses = Course::paginate(10);

return view('courses.index', compact('courses'));

sesudah :
Course::create($validated);

return redirect()
    ->route('courses.index')
    ->with('success', 'Mata kuliah berhasil ditambahkan.');

 **6. Form Tambah mata kuliah tidak memiliki directive @csrf**

 a. Letak kesalahan ada pada resources/views/courses/create.blade.php (Tag <form>)
 Laravel mewajibkan token proteksi Cross-Site Request Forgery (CSRF) untuk setiap request POST. Tanpa directive @csrf, Laravel akan menolak submit form dan menampilkan error 419 | Page Expired.

 b. Perbaikannya yaitu Menambahkan directive @csrf di dalam tag <form>.

 c. Bukti perbaikan 
 
 sebelum: 
<form action="{{ route('courses.store') }}" method="POST" class="space-y-5">
<div class="grid grid-cols-2 gap-4">

 sesudah:<form action="{{ route('courses.store') }}" method="POST" class="space-y-5">
 @csrf
<div class="grid grid-cols-2 gap-4">
